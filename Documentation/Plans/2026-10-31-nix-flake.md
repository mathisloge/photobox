# Nix Flake Implementation Plan

> **For agentic workers:** Execution method chosen by the author: **the main agent implements every task itself, in this session; subagents are used only for reviews.** Follow superpowers:executing-plans for the implementation, task by task. After each task's commit, dispatch one fresh reviewer subagent (superpowers:requesting-code-review). Give it the task's diff, that task's section of this plan, and the spec. Fix what it confirms, then move on to the next task. After Task 6, dispatch one fresh reviewer for the whole branch. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and develop Photobox through a Nix flake (package + dev shell), with CMake using plain `find_package`, CI on Nix, and Flatpak removed.

**Architecture:** A plain `flake.nix` (only input: nixpkgs `nixos-unstable`) applies an overlay from `Nix/` that adds the one dependency nixpkgs lacks (stdexec). `Nix/photobox.nix` builds Photobox with CMake and runs its tests; `Nix/devshell.nix` reuses its inputs plus dev tools. CMake no longer fetches anything.

**Tech Stack:** Nix flakes, nixpkgs nixos-unstable (Qt 6.12.0, GCC 16), CMake ≥ 3.30 + Ninja, Catch2 3, GitHub Actions.

**Spec:** `Documentation/Specs/2026-10-31-nix-flake-design.md` — read it before Task 1.

**Where this runs:** a fresh clone of branch `build/nix-flake` on the author's NixOS-WSL, which already has the prerequisites listed in Task 4 step 7. All commands below run from the repo root.

## Global Constraints

- Nix is the only supported build path. No CPM, no FetchContent downloads, no non-Nix fallback.
- CMake finds every dependency with `find_package(... CONFIG ...)`, except libgphoto2 (`pkg_check_modules`, unchanged) and Qt (unchanged lookup).
- Flake input: `nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable"`, nothing else.
- Systems: `x86_64-linux` and `aarch64-linux`.
- Keep `CMAKE_CXX_STANDARD 26` and `find_package(Qt6 6.12 ...)` from the working tree.
- stdexec commit `362cdc77738e958f1d12fddfb55229a98df29d8a`, `STDEXEC_ENABLE_ASIO=ON`, `STDEXEC_ASIO_IMPLEMENTATION=boost`.
- quill comes from nixpkgs `quill-log` (13.1.0), not nixpkgs `quill`.
- Versions are pinned only in `flake.lock` and `Nix/stdexec.nix`.
- No `/nix/store/<hash>-…` paths in committed files.
- `nix build` works offline in the sandbox, no `--impure`.
- quite is optional; CollageEditorApp stays out of the build.
- New files carry `SPDX-FileCopyrightText: 2026 Mathis Logemann <mathis.opensource@tuta.io>` / `SPDX-License-Identifier: GPL-3.0-or-later`, or a `REUSE.toml` annotation when they can't hold a comment.
- Commits use Conventional Commits (the repo's commit-msg hook enforces it) and **never** carry a `Co-Authored-By` trailer.
- C++ changes are limited to what the new versions require. If an existing test fails for reasons unrelated to the environment, stop and ask the author; don't disable it.
- Known and out of scope: `Photobox/Core/CrashCollection.cpp:97` calls `execl("PhotoboxSignalTracer", …)` with a relative path. Leave it.

## Review Focus

1. clangd in VS Code on NixOS can't find libstdc++ headers, because `compile_commands.json` names Nix's GCC wrapper. Expected: no "file not found" diagnostics. Test: Task 4, step 10.
2. PhotoboxApp started from `build/developer/runtime/` in the dev shell can't find a Qt platform plugin or QML modules (QtQuick.Controls, QtQuick.Effects, QtQuick.Dialogs, QtMultimedia). Expected: it starts. Test: Task 4, step 9.
3. The installed package (`nix run`) misses a Qt plugin or QML module after `wrapQtAppsHook`, e.g. qtmultimedia's backend or qtsvg. Expected: it starts. Test: Task 3, step 5.
4. The flake only evaluates for x86_64, which breaks the later Pi work. Expected: aarch64 outputs evaluate. Test: Task 2, step 11, and CI in Task 5.
5. VS Code with CMake Tools `configureOnOpen` configures before direnv has loaded the shell, then caches a failed configure. Expected: opening a fresh clone configures cleanly. Test: Task 4, step 12(b), a manual check.

- [ ] **Step 3: Write `Nix/stdexec.nix`**

`stdenv.mkDerivation` with:
- `src`: `fetchFromGitHub { owner = "NVIDIA"; repo = "stdexec"; rev = "362cdc77738e958f1d12fddfb55229a98df29d8a"; }`.
- `version = "0.11.0-unstable-<commit date>"`.
- `nativeBuildInputs = [ cmake ninja ]` and `propagatedBuildInputs = [ boost ]`.
- **Offline sources:** stdexec's CMake downloads two things at configure time, so provide both as fixed-output sources:
  - **rapids-cmake:** `fetchFromGitHub rapidsai/rapids-cmake`, at the tag matching the `rapids-cmake-version` default in the commit's `cmake/RAPIDS.cmake` (24.02 → `v24.02.00`).
  - **CPM.cmake:** `fetchurl`, at the version that rapids-cmake's `cpm/detail/download.cmake` expects.
- `cmakeFlags`:
  - `-DSTDEXEC_BUILD_TESTS=OFF`, `-DSTDEXEC_BUILD_EXAMPLES=OFF`
  - `-DSTDEXEC_ENABLE_ASIO=ON`, `-DSTDEXEC_ASIO_IMPLEMENTATION=boost`
  - `-DFETCHCONTENT_FULLY_DISCONNECTED=ON`, `-DFETCHCONTENT_SOURCE_DIR_RAPIDS-CMAKE=${rapids-cmake}`
  - `-DCPM_DOWNLOAD_LOCATION=${cpm}`
  - `-DCPM_USE_LOCAL_PACKAGES=ON`, so `rapids_cpm_find(Boost …)` takes nixpkgs' Boost.
- `postPatch`: `substituteInPlace cmake/Modules/ConfigureASIO.cmake --replace-fail "Boost::asio" "Boost::headers"`. nixpkgs Boost is built with b2 and exports no `Boost::asio`.
- `Flatpak/stdexec.yaml` shows how the older commit was built offline. Use it for reference only.

Expected:
- the build succeeds;
- the config file exists and the `test` prints `ok`;
- at least one cmake file mentions `asioexec`;
